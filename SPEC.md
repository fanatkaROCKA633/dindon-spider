# Spec: DindonSpider — пиксельный паук на рабочем столе

> Статус: v1 сделана в `ilyuha_plg` (SpiderWidget); это копия с паутиной — см. раздел
> «Паутина» в конце. Данные копии — в `%LOCALAPPDATA%\DindonSpider\`, один экземпляр —
> по своему имени, поэтому обе копии работают рядом. Голова по умолчанию — «Диндон».

## Objective

Виджет-игрушка для Windows: пиксельная голова на шести паучьих ногах живёт
поверх рабочего стола, ползает по иконкам, рамкам окон и панели задач,
цепляется за них ногами, иногда срывается и падает, иногда охотится за
курсором и прыгает на него. Паука можно схватить мышью и бросить. Если
перетащить на паука файл, папку или иконку — паук «съедает» её, а объект
уходит **в корзину** (обратимо).

Стиль — пиксель-арт: голова — пиксельный портрет, сделанный из фото
пользователя (палитра ~10 цветов + тёмный контур), ноги — простые серые
пиксельные линии.

Пользователь — один человек на своём ПК. Сетевых функций, телеметрии и
аккаунтов нет.

### Пользовательские истории

1. Запускаю `SpiderWidget.exe` — паук появляется внизу экрана и начинает
   бродить, не мешая кликать по остальному.
2. Паук забирается на иконку рабочего стола / верхнюю кромку окна / панель
   задач и перемещается по ним, ноги видно цепляются за край.
3. Время от времени паук срывается с иконки и падает вниз, пока не приземлится
   на другую поверхность или на нижний край экрана.
4. Иногда паук замечает курсор поблизости, подкрадывается и прыгает на него.
5. Хватаю паука мышью, тащу и отпускаю с размаху — он летит по инерции и
   падает.
6. Тащу ярлык, файл или папку на паука — паук проигрывает анимацию «съел»,
   объект оказывается в корзине.
7. Закрываю виджет через иконку в трее → «Выход».

## Capability Map

| Module id | Ответственность | Зависит от |
|---|---|---|
| `overlay` | маленькое прозрачное окно поверх всех, рисует спрайт, пропускает клики мимо паука, захват и бросок мышью, иконка в трее | — |
| `targets` | список прямоугольников-опор: иконки рабочего стола, рамки окон, панель задач | — |
| `spider` | поведение: ходьба, лазание, процедурные ноги, срыв и падение, охота за курсором, полёт после броска, анимации | `overlay`, `targets` |
| `recycle-drop` | приём перетаскивания и отправка файлов в корзину с фильтром безопасности | `overlay` |

Порядок сборки: `overlay` → `targets` → `spider` → `recycle-drop`.

Модули маленькие, поэтому они описаны разделами этого файла, а не отдельными
`SPEC-<module>.md`. Если какой-то разрастётся — вынесем.

## Tech Stack

- C# 12, **.NET 8**, WinForms (`net8.0-windows`), Windows 10 21H2+ / 11.
- Win32 / COM через P/Invoke (`user32`, `dwmapi`, `shell32`); без сторонних
  NuGet-пакетов в приложении.

  пользователь сам (см. Boundaries).

## Модули

### `overlay`

- Окно **размером с паука** (~96×96 px при масштабе 3×), а не на весь экран:
  проще пропускать клики и принимать drop только на самом пауке.
- Стили: `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TOPMOST`
  — не видно в Alt-Tab и на панели задач, не крадёт фокус.
- Поверх всех окон: раз в 0,5 с окно паука заново поднимается наверх слоя
  TopMost (иначе его перекрывают другие окна «поверх всех», открытые позже).
  Меню Пуск, экран блокировки и эксклюзивный полноэкранный режим не
  перекрываются — это ограничение Windows для обычных программ.
- Попиксельная прозрачность через `UpdateLayeredWindow`; клики по прозрачным
  пикселям проходят насквозь (`WM_NCHITTEST` → `HTTRANSPARENT`), по
  непрозрачным (голова и ноги) — ловятся окном.
- Захват: зажал ЛКМ на пауке → он висит под курсором и дрыгает ногами;
  отпустил → скорость броска = смещение курсора за последние ~100 мс,
  ограничена сверху; дальше паук летит по физике. Короткий клик без движения
  — просто «ой», паук падает с места.
- Графика: голова — спрайт 24×38 с палитрой (строки символов + словарь
  цветов в `Sprites.cs`), получен из фото однократно скриптом вне проекта;
  тёмный контур, чтобы читалась на любом фоне; ноги — пиксельные линии
  (Брезенхэм) толщиной 1 логический пиксель, рисуются по координатам из
  `Legs`. Всё масштабируется nearest-neighbor ×3, без сглаживания; отдельных
  файлов с артом в v1 нет.
- Учёт DPI: `PerMonitorV2`; паук не уходит за пределы виртуального экрана
  (несколько мониторов).
- Трей: «Пауза», «Выход».

**Критерии:**
- Клик рядом с пауком (по прозрачной области окна) попадает в окно под ним.
- Паука можно схватить и бросить; брошенный вбок летит по дуге, а не падает
  вертикально.
- В Alt-Tab паука нет; фокус у активного окна не пропадает.
- CPU в простое ≤ 2 % одного ядра, память ≤ 80 МБ.

### `targets`

Отдаёт `IReadOnlyList<Surface>`, опрос ~2 раза в секунду.

- **Иконки рабочего стола:** `IShellWindows.FindWindowSW(SWC_DESKTOP)` →
  `IFolderView.GetItemPosition` + размер иконки. Без чтения памяти Explorer.
- **Окна:** `EnumWindows` → видимые, не свёрнутые, не cloaked
  (`DWMWA_CLOAKED`), реальная рамка через `DWMWA_EXTENDED_FRAME_BOUNDS`.
  Опорой считается только **верхняя кромка**, не перекрытая окнами выше по
  Z-порядку.
- **Панель задач:** `Shell_TrayWnd` (+ `Shell_SecondaryTrayWnd` на других мониторах).
- Если иконки скрыты или Explorer перезапустился — список иконок пуст, ошибок нет.

**Критерии:**
- Передвигаю окно — в течение ≤ 0,5 с опора переезжает вместе с ним.
- Падение Explorer не роняет виджет.

### `spider`

Состояния: `Idle → Walk → Climb → Hang → Slip/Fall → Land → Walk`, плюс
`Hunt → Jump → Pounce`, `Grabbed → Thrown → Fall` и `Eat` (запускает
`recycle-drop`).

- Физика — фиксированный шаг 60 Гц, гравитация, приземление на ближайшую
  опору под пауком или на нижний край рабочей области.
- Ноги: **6 штук** (по 3 с каждой стороны), каждая — 2 звена с аналитической
  IK; ступня держится на точке кромки, пока тело не уйдёт дальше порога,
  тогда делает шаг. Походка — чередующиеся тройки (как у насекомых): пока
  одна тройка шагает, другая держит.
- Срыв: пока паук висит на иконке, каждую секунду шанс `SlipChancePerSecond`
  (по умолчанию 3 %) — проигрывает «соскальзывание» и падает.
- Цель выбирается случайно среди достижимых опор; паук не «прыгает» сквозь
  экран — доходит до грани пешком, в пределах радиуса `ClimbRadius` (900 px).
- Охота: положение курсора читается опросом `GetCursorPos` в такте физики
  (без глобальных хуков мыши). Если курсор ближе `HuntRadius` (по умолчанию
  300 px) и паук стоит на опоре, раз в секунду шанс `HuntChancePerSecond`
  (по умолчанию 5 %) начать охоту: паук разворачивается, подкрадывается,
  приседает и прыгает по баллистической дуге в точку, где курсор был в момент
  прыжка. Курсор он не двигает и не блокирует — «поймал» только визуально,
  потом падает. Не чаще одной охоты в `HuntCooldown` (по умолчанию 20 с).
- Бросок: из `Grabbed` паук переходит в `Thrown` с начальной скоростью от
  `overlay`; ноги в полёте поджаты, при касании опоры — `Land`.
- Логика (`SpiderBrain`, `Physics`, `Legs`) не знает про WinForms — чистые
  классы, на вход время и список опор, чтобы тестировать без окна.

**Критерии:**
- При фиксированном seed падение с иконки заканчивается приземлением на
  опору под ней (тест).
- Ступни ног в состоянии `Hang` лежат на кромке опоры с точностью ±1 px (тест).
- Прыжок на курсор с заданной стартовой точкой попадает в точку курсора
  ±2 px, если по пути нет опоры (тест).
- Бросок со скоростью вправо даёт смещение вправо к моменту приземления (тест).
- Визуально (ручная проверка): паук лазает по иконкам и окнам, срывается
  примерно раз в полминуты висения, иногда охотится за курсором.

### `recycle-drop`

- Окно паука — drop target для `DataFormats.FileDrop`. Пока над пауком тащат
  файл, он открывает рот.
- Удаление: `SHFileOperation(FO_DELETE)` с флагами
  `FOF_ALLOWUNDO | FOF_NOCONFIRMATION | FOF_WANTNUKEWARNING | FOF_SILENT`.
  Если Windows не может положить файл в корзину (слишком большой, том без
  корзины), она **покажет предупреждение**, а не удалит молча.
- Фильтр **до** вызова (отказ = паук мотает головой, ничего не удаляется):
  - только локальные пути на фиксированных дисках (не сеть, не UNC,
    не съёмные носители — у них нет корзины);
  - не корень диска, не `%WINDIR%`, `%ProgramFiles%`, `%ProgramFiles(x86)%`,
    не профиль пользователя целиком, не сам рабочий стол;
  - элементы без пути в файловой системе («Этот компьютер», «Корзина») в
    `FileDrop` не приходят — их просто игнорируем.
- Принимаются файлы, ярлыки и **папки** (папка уходит в корзину целиком, со
  всем содержимым). Для очень большой папки Windows может сказать, что она не
  поместится в корзину, — тогда срабатывает предупреждение
  `FOF_WANTNUKEWARNING`, и пользователь может отказаться.
- Ярлык удаляется как ярлык: цель ярлыка не трогаем.
- Лог: `%LOCALAPPDATA%\SpiderWidget\log.txt` — время, путь, результат.
  Только локально.

**Критерии:**
- Файл или папка, брошенные на паука, оказываются в корзине и
  восстанавливаются оттуда.
- `C:\`, `C:\Windows`, `C:\Program Files`, `C:\Users\<user>`,
  `C:\Users\<user>\Desktop`, `\\server\share\x.txt`, путь на флешке — отказ,
  объект на месте (тест фильтра). Обычная папка на рабочем столе — принимается.
- Перетаскивание мимо паука ничего не удаляет.

## Code Style

```csharp
namespace SpiderWidget.Spider;

/// Одна нога: плечо на теле, ступня на опоре.
public sealed class Leg(Vector2 hipOffset, float upper, float lower)
{
    public Vector2 Foot { get; private set; }

    // Шагаем, только когда ступня отстала дальше порога: иначе ноги дрожат.
    public bool NeedsStep(Vector2 hip, float threshold) =>
        Vector2.Distance(hip + hipOffset, Foot) > threshold;
}
```

- `nullable enable`, `TreatWarningsAsErrors`, file-scoped namespaces.
- Случайность — только через переданный `Random` (seed в тестах), никаких
  `Random.Shared` в логике.
- PascalCase для типов и членов, `_camelCase` для приватных полей.
- P/Invoke — только в `Native/`, через `LibraryImport`.
- Числа-настройки (шанс срыва, скорость, масштаб) — константы в одном
  `Tuning.cs`, без конфиг-файла в первой версии.
- Комментарии — там, где решение неочевидно.

## Testing Strategy

- **xUnit, unit:** `Physics`, `Legs`, `SpiderBrain` (детерминированный seed,
  включая охоту и бросок), расчёт скорости броска в `Grab`, фильтр путей в
  `RecycleBin`. Цель — покрытие логики ≥ 80 %.
- **Ручная проверка** (не автоматизируется): прозрачность и click-through,
  реальные иконки и окна, drop из Проводника, несколько мониторов, DPI 100/150 %.
- Реальное удаление в тестах — только во временной папке `%TEMP%`,
  и только через фильтр.

## Boundaries

- **Always:** прогонять `dotnet build` и `dotnet test` перед коммитом; удалять
  только в корзину; проверять путь фильтром до удаления; держать логику
  отдельно от WinForms.
- **Ask first:** новые NuGet-пакеты; автозапуск при входе в Windows; любые
  права администратора; установка .NET SDK (ставит пользователь сам);
  цепляние за элементы внутри приложений (UI Automation).
- **Never:** коммитить исходное фото (`photo_*.jpg`) — на нём есть
  посторонние люди; в коде только пиксельный спрайт головы;
  безвозвратное удаление (`File.Delete`, `Directory.Delete`,
  `Shift+Del`-флаги); удалять что-то без явного drop от пользователя; хуки
  клавиатуры/мыши во всей системе; внедрение в чужие процессы или чтение их
  памяти; сетевые запросы.

## Success Criteria

1. `dotnet build` и `dotnet test` проходят без предупреждений.
2. Пиксельная голова на 6 пиксельных ногах ходит, лазает по иконкам, рамкам
   окон и панели задач, ноги видно цепляются за кромки.
3. С иконок паук периодически срывается и падает, приземляясь на опору ниже.
4. Иногда паук охотится за курсором и прыгает на него, не мешая мыши.
5. Паука можно схватить мышью и бросить — он летит по инерции.
6. Файл или папка, брошенные на паука, попадают в корзину; опасные пути
   отклоняются.
7. Паук не мешает работе: клики мимо него проходят насквозь, фокус не крадёт,
   CPU ≤ 2 %.
8. Закрывается через трей, повторный запуск не плодит второго паука.

## После v1: выбор головы

- Головы: «Диндон» (26×34) и «Лёвчик» (26×32) — мультяшные пиксельные портреты
  по фото пользователя, в одном стиле. В этой копии «Лёвчик» заменил «Илюху»

## Паутина (только в DindonSpider)

**Когда.** Для каждого верхнего угла рабочей области главного монитора (зона —
квадрат `WebRadius` = 240 px от угла) считается, сколько секунд курсор туда не
заходил. ≥ `WebQuietSeconds` (60 с) и паутины в углу нет — после ближайшей паузы
паук идёт плести. Позиция курсора — опросом в такте, хуков нет.

**Путь.** `WebApproach` (бег к краю экрана, 150 px/с) → `EdgeClimb` (по краю
экрана вверх, 160 px/с) → `WebWalk` (к месту на паутине) → `Weave` (≈ 8 с: сначала
6 радиальных нитей, потом 5 провисающих дуг) → `OnWeb`. Идти можно, только если
край экрана достижим по текущей опоре и паук ниже паутины.

**На паутине.** `OnWeb` 5–15 с, затем с шансом 60 % — `Descend` на 120–380 px
(не ниже опоры под паутиной) → `Dangle` 3–8 с, покачиваясь → `Ascend` обратно.
После 1–3 минут на паутине — `WebLeave`: спуск по нити до опоры, паутина остаётся;
позже паук может вернуться на готовую паутину (шанс 25 % после паузы).

**Смахивание.** Отрезок, пройденный курсором за кадр, рвёт сплетённые нити ближе
`WipeRadius` (14 px). Целых < 35 % — паутины нет. Отрезок поперёк нити, на которой
висит паук, — нить рвётся. Паутина пропала или нить порвана — паук падает (`Fall`).

**Окна.** У каждой паутины своё layered-окно, у нити — своё; оба с
`WS_EX_TRANSPARENT`: клики проходят насквозь. Паутина перерисовывается только при
изменении, нить — пока паук на ней.

**Настройка.** Трей → «Паутина» (вкл. по умолчанию), `webs=on|off` в settings.txt.
Выключили — все паутины исчезают, паук с паутины падает.

**Проверено:** тесты `WebTests` (геометрия, плетение, смахивание, тишина углов,
выключение, поход и посиделки, спуск-подъём, падение при смахивании и обрыве нити);
вживую — плетение, посиделки, спуск-подъём на релизной сборке, смахивание курсором.
**Не проверено:** несколько мониторов, переключатель в трее руками.

## Установка и иконка (только в DindonSpider)

- exe называется `DindonSpider.exe`, иконка — `src/SpiderWidget/Assets/spider.ico`
  (голова «Диндон» с лапами, 16–256 px; сгенерирована из спрайта скриптом вне проекта).
- `install.cmd` → `tools/install.ps1`: проверяет .NET 8 SDK, собирает exe в
  `%LOCALAPPDATA%\DindonSpider\app`, создаёт ярлык «Паук Диндон» на рабочем столе и
  в меню Пуск, по вопросу — в автозагрузке, запускает. Повторный запуск — обновление.
- `uninstall.cmd` → `tools/uninstall.ps1`: останавливает, удаляет ярлыки и только
  папку `app`; настройки и лог остаются.
- Готового exe в репозитории нет — его собирает установщик.
